# Security Summary

SB Khush Cloud's multi-tenant eCommerce, Self-Pickup, and Sales Management platform enforces strict Role-Based Access Control (RBAC), tenant isolation, and fail-closed validation across the React Router frontend, Express backend (`/api/*`), Cloud Functions (`functions/src/index.ts`), Firestore Security Rules (`firestore.rules`), and Firebase Storage Rules (`storage.rules`).

## Strict Role Separation & Tenant Isolation
- **Zero Privilege Escalation**: Allowed sales roles remain strictly scoped to `salesman`, `senior_salesman`, `sales_manager`, and `referral_agent`. Sales team accounts cannot receive or self-promote to `super_admin`.
- **Super Admin Exclusive Control (`/super-admin/*` and `/admin/*`)**: Strictly protected by `SuperAdminLayout` route guards, `isSuperAdmin()` rules, custom claims (`onPlatformAdminWritten`), `platform_admins` records, and backend Firebase ID token verification.
- **Merchant Tenant Isolation (`shops/{shopId}`)**: Public storefronts read only the strict 19-key whitelisted non-PII `shops_public/{shopId}` projection and `shops/{shopId}/settings/public`. Admin and permitted staff (`settings` / `appearance`) mutations reconstruct the exact sanitized `shops_public` document without `merge: true`, preserving `isValidShopPublicDoc()` compliance while zero CNIC fields ever project onto `shops_public`.
- **Separated `get` vs `list` Rules**: All tenant and sales collections (`orders`, `payment_receipts`, `platform_payment_receipts`, `cnic_registry`, `inventory_logs`, `customers`, `notifications`, `activity_logs`, `salesExpenses`, `salesBonusRecommendations`) split `allow get` (`isValidId`) from `allow list` so valid collection queries never fail rules evaluation due to unbound document ID variables.
- **Global Atomic One-CNIC-One-Shop Registry (`cnic_registry/{hmacKey}`)**: Store registration routes exclusively through server-verified endpoints (`registerShopWithCnic` Cloud Function with `defineSecret('CNIC_HMAC_SECRET')` or `POST /api/shops/register`). Raw CNIC digits are normalized server-side and keyed via HMAC-SHA256 inside `cnic_registry/{hmacKey}` using atomic preconditions alongside `shop_slugs/{slug}` and `shops/{shopId}`. Firestore rules enforce `existsAfter` / `getAfter` cross-document atomicity so standalone client writes to any single registry/shop doc are rejected.
- **Server-Side Shop Deletion & Archival (`deleteShopCompleteAdmin`)**: Invokes `deleteShopCompleteAdmin` (`us-central1`) to purge subcollections, `shops_public`, `shop_slugs`, all staff `shopMemberships` (with custom claims rebuilt under Firebase's 1000-byte ceiling), `shops/{shopId}/` & `platform/payments/{shopId}/` Storage folders, retain CNIC lock archival state, and write immutable audit logs to `archived_shops/{shopId}` and `platform_activity_logs`.
- **Firebase Storage, CORS & Magic-Byte Validation**: `storage.rules` enforces `<= 5 MB`, `image/(jpeg|jpg|png|webp|gif)`, and custom metadata (`shopId` + `uploaderUid`) on checkout, subscription, and expense receipts; client upload helpers verify binary JPEG/PNG/WebP/GIF magic headers via `detectImageMimeFromMagicBytes` and resolve canonical non-empty MIME types (`resolveUploadContentType`); `cors.json` allows official SB Khush origins, GitHub Pages demo domain, and local dev.
- **PII & Secret Redaction**: `errorHandler.ts` redacts 13-digit CNIC numbers and JWT Bearer tokens prior to console logging/throwing, and `mapFirebaseErrorMessage` maps Auth/Firestore/Storage/Functions codes to clear user-facing errors.
- **Air-Gapped Demo Super Admin Sandbox (`/demo_env/default`)**: Demo Super Admin sessions (`demo-admin@sbkhush.com`, `demo_super_admin == true`, `account_type == 'DEMO'`) enforce `isNotDemoAccount()` and `isDemoSuperAdmin()` across `firestore.rules`, `storage.rules`, `functions/src/index.ts`, and `AuthContext.tsx`, locking claims to `super_admin: false`, `shops: {}`, `sales_role: null`, and routing all client Firestore/Storage operations through `scopedCollection`, `scopedDoc`, and `scopeStoragePath` (`demo_env/default/...`) with server callables `provisionDemoSuperAdmin`, `issueDemoAdminToken`, and `resetDemoEnvironmentAdmin`.
